# Ignite — 点亮你的想法：多智能体方案评审 Skill

一个基于 Claude Code 的结构化多智能体辩论系统，通过专家评审、对抗性辩论和公正裁决，将一个原始想法转化为经过实战检验的执行方案。

## 为什么需要 Ignite？

无论单个 AI 多强大，都有盲区。Ignite 强制多个专家视角相互辩论——暴露隐藏假设、发现风险、产出经得起推敲的方案。

## 工作流程

```
/ignite <你的任务或想法>
```

7 阶段流水线：

| 阶段 | 做什么 | 产出 |
|------|--------|------|
| 0. 需求澄清 | 聚焦式问答，填补任务描述中的空白 | 结构化任务文档 |
| 1. 生成方案 | Planner 智能体产出详细执行方案 | 方案 v1 |
| 2. 多视角评审 | 3 个专家 Suggestor 从不同角度评审 | 9-15 条具体建议 |
| 3. 结构化辩论 | Planner vs Suggestors 针对每条建议辩论（最多 3 轮） | 带论证的辩论记录 |
| 4. 裁判决议 | 公正的 Judge 对每条建议裁决 ADOPT / MODIFY / REJECT | 附理由的裁决 |
| 5. 用户确认 | 用户审阅并可覆写裁决 | 最终决策清单 |
| 6. 修订方案 | Planner 整合确认的变更 | 方案 v2（带差异标记） |
| 7. 更新项目状态 | 追踪任务状态和跨任务规律 | PROJECT_STATE.md |

**辩论**（第 3 阶段）是核心价值——真正的对抗，不是走过场。Planner 必须用证据捍卫决策，Suggestors 在被反驳时调整立场。这种对抗过程能发现单次评审无法触及的洞察。

## 实测效果

基于多个真实任务评估，覆盖不同领域：

### 建议质量

| 任务 | 评审专家 | 建议数 | 采纳 | 修改 | 拒绝 |
|------|---------|--------|------|------|------|
| CI/CD 流水线设计 | Tech Lead / DevOps / 质量保障 | 9 | 8 (89%) | 1 (11%) | 0 |
| 社区咖啡馆开业 | 运营 / 财务 / 社区营销 | 9 | 8 (89%) | 1 (11%) | 0 |
| 客服 NPS 提升 | 客户成功 / 客服运营 / 数据分析 | 9 | 8 (89%) | 0 | 1 (11%) |

**共生成 27 条建议，95% 采纳率**——几乎每条建议都被认为有足够价值值得整合或调整后采纳。

### 相比单智能体方案的关键提升

| 维度 | 无 Ignite | 有 Ignite |
|------|----------|----------|
| 盲区发现 | 方案中的假设无人挑战 | 3 个专家视角捕捉遗漏 |
| 风险识别 | 隐藏到执行阶段才暴露 | 提前辩论并制定缓解措施 |
| 方案质量 | 单一视角 | 经过多方利益博弈的压力测试 |
| 决策质量 | 接受或拒绝 | 采纳 / 修改 / 拒绝 + 保留洞察 |
| 可追溯性 | 无决策记录 | 每条建议的完整辩论历史 |

### 辩论带来的具体收益

- **CI/CD**：辩论推翻了蓝绿部署建议——滚动更新配合 tag 保留被证明同样快速且更节省资源
- **社区咖啡馆**：辩论暴露了 3 个月现金流盲区，促使建立三版回本测算模型，捕捉到原始方案遗漏的场景
- **客服 NPS**：辩论指出 12 人团队无法运行有统计意义的 A/B 测试，转为前后对比方案——同样的数据驱动思维，可行规模下执行

## 设计原则

- **该快就快**——输入已经清晰时，需求澄清阶段快速通过
- **展示而非堆砌**——阶段间给摘要，需要时提供完整细节
- **辩论即产品**——浅层辩论浪费精力，系统推动实质性对抗
- **保持中立**——编排者不偏袒任何一方
- **尊重用户时间**——显而易见的建议跳过完整辩论，精力集中在争议点

## 安装

1. 将 `ignite/` skill 目录复制到 `~/.claude/skills/ignite/`
2. 在 `~/.claude/CLAUDE.md` 中添加：

```markdown
# ignite
- **ignite** (`~/.claude/skills/ignite/SKILL.md`) - multi-agent plan review system. Trigger: `/ignite`
When the user types `/ignite`, invoke the Skill tool with `skill: "ignite"` before doing anything else.
```

3. 在任意 Claude Code 会话中使用 `/ignite <你的想法>`

## 文件结构

```
ignite/
├── SKILL.md          # 核心 skill 定义（完整流水线）
├── evals/
│   └── evals.json    # 评估用例
├── .claude/
│   └── settings.json # Skill 配置
└── references/       # 参考材料
```

每个任务创建缓存目录，按阶段保存完整产物，确保可追溯：

```
task_cache/task-<slug>-<date>/
├── 00_task.md           # 澄清后的需求
├── 01_plan_v1.md        # 初始方案
├── 02_suggestions.md    # 多视角评审
├── 03_debates.md        # 结构化辩论
├── 04_verdicts.md       # 裁判决议
├── 05_user_decisions.md # 用户最终决策
└── 06_plan_v2.md        # 修订后方案
```
